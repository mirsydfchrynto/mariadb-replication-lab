Langkah 2 — Membuat Routine transaksi1 (START TRANSACTION Tanpa COMMIT)
🖱 Aksi Klik di phpMyAdmin Windows:
  1. Pastikan sedang berada di dalam database rumah_sakit.
  2. Klik tab Routines di deretan menu atas (jika tidak terlihat, klik More → Routines).
  3. Klik tombol Create new routine (atau Add routine).
  4. Pada kotak Routine name, ketik: transaksi1
  5. Pada bagian Parameters, klik tombol Drop di sebelah kanan agar baris parameter terhapus.
  6. Klik tombol Copy Kode di bawah ini, lalu tempelkan (Ctrl + V) ke dalam kotak besar Definition:
BEGIN
START TRANSACTION;
INSERT INTO `pasien` (`id_pasien`, `nama_pasien`, `alamat_pasien`, `jenis_kelamin`)
VALUES (6, 'Hanif', 'Jl. Babakan Loa No. 22', 'L');
SELECT * FROM pasien;
END
  1. Scroll ke paling bawah jendela pop-up, klik tombol Go.
  2. Setelah transaksi1 muncul di daftar Routines, klik tombol Execute pada baris transaksi1. Tunjuk bahwa data ID 6 (Hanif) muncul di hasil eksekusi.
  3. Sekarang klik tabel pasien di panel kiri: tunjukkan bahwa jumlah data masih tetap 5 baris (data Hanif belum masuk permanen karena belum ada perintah COMMIT).
🎙 Kalimat yang Diucapkan:
"Kita mulai dengan membuka menu Routines lalu klik Create new routine. Untuk routine pertama kita beri nama transaksi1, lalu parameternya kita drop. Pada bagian Definition, kita memulai transaksi dengan START TRANSACTION, menyisipkan data pasien ID 6 bernama Hanif tanpa perintah COMMIT, lalu menampilkan tabel pasien dan ditutup dengan END. Kita klik Go lalu klik Execute. Di sini data Hanif muncul pada hasil eksekusi sementara. Namun ketika kita cek langsung tabel pasien di menu Browse, data Hanif belum tersimpan secara permanen karena belum dilakukan perintah COMMIT."

Langkah 4 — Membuat Routine transaksi3 (Perintah ROLLBACK)
🖱 Aksi Klik di phpMyAdmin Windows:
  1. Buka tab Routines → klik Create new routine.
  2. Isi Routine name: transaksi3, lalu klik Drop pada Parameters.
  3. Copy kode di bawah ini ke kotak Definition:
BEGIN
START TRANSACTION;
UPDATE pasien
SET nama_pasien = 'Septin'
WHERE id_pasien = 3;
ROLLBACK;
COMMIT;
SELECT * FROM pasien;
END
  1. Klik Go, lalu klik Execute pada transaksi3.
  2. Tunjukkan bahwa pasien ID 3 tetap bernama Budi Raharjo (tidak berubah menjadi Septin karena adanya perintah ROLLBACK).
🎙 Kalimat yang Diucapkan:
"Berikutnya kita membuat routine transaksi3 untuk mempraktikkan perintah ROLLBACK. Di sini kita mencoba mengubah nama pasien pada ID 3 menjadi Septin, namun diikuti perintah ROLLBACK. Saat kita simpan dan klik Execute, terlihat nama pasien ID 3 tetap Budi Raharjo karena perubahan tersebut telah dibatalkan oleh perintah ROLLBACK."
Langkah 5 — Membuat Routine transaksi4 (Modifikasi ROLLBACK & COMMIT Sesuai Modul)
🖱 Aksi Klik di phpMyAdmin Windows:
  1. Buka tab Routines → klik Create new routine.
  2. Isi Routine name: transaksi4, lalu klik Drop pada Parameters.
  3. Copy kode di bawah ini ke kotak Definition:
BEGIN
START TRANSACTION;
INSERT INTO `pasien` (`id_pasien`, `nama_pasien`, `alamat_pasien`, `jenis_kelamin`)
VALUES (7, 'Rudi', 'Jl. Kebon Jeruk No. 14', 'L');
ROLLBACK;
UPDATE pasien
SET nama_pasien = 'Septin'

COMMIT;
SELECT * FROM pasien;
END
  1. Klik Go, lalu klik Execute pada transaksi4.
  2. Klik tabel pasien: tunjukkan bahwa ID 7 (Rudi) batal masuk karena di-ROLLBACK, sedangkan ID 3 kini resmi berubah menjadi Septin karena di-COMMIT.
🎙 Kalimat yang Diucapkan:
"Selanjutnya pada transaksi4 sesuai modul praktikum, kita menyisipkan pasien baru ID 7 bernama Rudi lalu kita ROLLBACK, kemudian kita lakukan UPDATE nama pasien ID 3 menjadi Septin lalu kita COMMIT. Setelah kita klik Execute dan melihat tabel pasien, data ID 7 batal masuk karena ROLLBACK, sedangkan nama pasien ID 3 berhasil berubah menjadi Septin karena disahkan oleh COMMIT."
Langkah 6 — Membuat Routine transaksi5 (SAVEPOINT point1 & ROLLBACK TO point1)
🖱 Aksi Klik di phpMyAdmin Windows:
  1. Buka tab Routines → klik Create new routine.
  2. Isi Routine name: transaksi5, lalu klik Drop pada Parameters.
  3. Copy kode di bawah ini ke kotak Definition:
BEGIN
START TRANSACTION;
INSERT INTO `pasien` (`id_pasien`, `nama_pasien`, `alamat_pasien`, `jenis_kelamin`)
VALUES (8, 'Dudung', 'Jl. Cimahi No. 11', 'L');
SAVEPOINT point1;
INSERT INTO `pasien` (`id_pasien`, `nama_pasien`, `alamat_pasien`, `jenis_kelamin`)
VALUES (9, 'Maman', 'Jl. Garut No. 5', 'L');
ROLLBACK TO point1;
INSERT INTO `pasien` (`id_pasien`, `nama_pasien`, `alamat_pasien`, `jenis_kelamin`)
VALUES (10, 'Ujang', 'Jl. Tasikmalaya No. 9', 'L');
COMMIT;
SELECT * FROM pasien;
END
  1. Klik Go, lalu klik Execute pada transaksi5.
  2. Klik tabel pasien: tunjukkan bahwa ID 8 (Dudung) dan ID 10 (Ujang) masuk ke tabel, sedangkan ID 9 (Maman) batal masuk karena terkena ROLLBACK TO point1.
🎙 Kalimat yang Diucapkan:
"Berikutnya kita membuat routine transaksi5 untuk menguji SAVEPOINT. Kita menambahkan pasien ID 8 bernama Dudung, lalu membuat SAVEPOINT point1. Setelah itu kita menambahkan ID 9 bernama Maman, namun kita batalkan ke titik point1 menggunakan ROLLBACK TO point1, dilanjutkan menambah ID 10 bernama Ujang dan COMMIT. Hasilnya pada tabel pasien: ID 8 Dudung dan ID 10 Ujang berhasil tersimpan, sedangkan ID 9 Maman dibatalkan karena kembali ke titik point1."
Langkah 7 — Membuat Tabel obat & transaksi_obat Beserta Relasi Designer
🖱 Aksi Klik di phpMyAdmin Windows:
  1. Klik database rumah_sakit di panel kiri → klik tab SQL di bagian atas.
  2. Copy kode di bawah ini ke kotak SQL lalu klik Go:
CREATE TABLE obat (
  id_obat INT(6) NOT NULL AUTO_INCREMENT PRIMARY KEY,
  kode_obat VARCHAR(5) NOT NULL,
  nama_obat VARCHAR(30) NOT NULL,
  harga INT(10) NOT NULL,
  stok INT(5) NOT NULL
) ENGINE=InnoDB;

CREATE TABLE transaksi_obat (
  id_transaksi INT(6) NOT NULL AUTO_INCREMENT PRIMARY KEY,
  id_pasien INT(3) NOT NULL,
  id_obat INT(6) NOT NULL,
  jumlah INT(5) NOT NULL,
  total_harga INT(10) NOT NULL,
  INDEX (id_pasien),
  INDEX (id_obat),
  CONSTRAINT fk_to_pasien FOREIGN KEY (id_pasien) REFERENCES pasien(id_pasien) ON DELETE CASCADE ON UPDATE CASCADE,
  CONSTRAINT fk_to_obat FOREIGN KEY (id_obat) REFERENCES obat(id_obat) ON DELETE CASCADE ON UPDATE CASCADE
) ENGINE=InnoDB;

INSERT INTO obat (id_obat, kode_obat, nama_obat, harga, stok) VALUES
(1, 'A001', 'Paracetamol', 5000, 100),
(2, 'A002', 'Amoxicillin', 10000, 50),
(3, 'A003', 'Betadine', 15000, 100);
  1. Klik database rumah_sakit → klik tab More → Designer untuk memperlihatkan garis relasi antara pasien, transaksi_obat, dan obat.
  2. Klik tabel obat di panel kiri untuk memperlihatkan stok awal: Paracetamol = 100, Amoxicillin = 50, Betadine = 100.
🎙 Kalimat yang Diucapkan:
"Selanjutnya untuk mempraktikkan Trigger, kita membuat dua tabel tambahan yaitu tabel obat dan tabel transaksi_obat yang berelasi Foreign Key CASCADE dengan tabel pasien, serta mengisi tiga data obat awal yaitu Paracetamol dengan stok 100, Amoxicillin stok 50, dan Betadine stok 100. Pada menu Designer terlihat tabel pasien dan tabel obat sudah terhubung ke tabel transaksi_obat."
Langkah 8 — Membuat & Menguji Trigger tg_stok_obat
🖱 Aksi Klik di phpMyAdmin Windows:
  1. Klik tabel transaksi_obat di panel kiri → klik tab Triggers di menu atas.
  2. Klik Create new trigger (atau Add trigger):
    • Trigger name: tg_stok_obat
    • Table: transaksi_obat
    • Time: AFTER
    • Event: INSERT
  3. Copy kode di bawah ini ke kotak Definition lalu klik Go:
UPDATE obat SET stok = stok - NEW.jumlah WHERE id_obat = NEW.id_obat
  1. Sekarang uji Trigger tersebut: klik tab Insert pada tabel transaksi_obat, lalu isi:
    • id_transaksi: 1
    • id_pasien: pilih 6 (Hanif)
    • id_obat: pilih 1 (Paracetamol)
    • jumlah: 15
    • total_harga: 75000
    Klik tombol Go.
  2. Klik tabel obat di panel kiri: tunjukkan stok Paracetamol otomatis berkurang dari 100 menjadi 85!
🎙 Kalimat yang Diucapkan:
"Pada tabel transaksi_obat kita buka menu Triggers lalu klik Create new trigger. Kita beri nama tg_stok_obat, waktu AFTER, dan event INSERT, dengan perintah UPDATE obat SET stok = stok - NEW.jumlah WHERE id_obat = NEW.id_obat, lalu klik Go. Sekarang kita uji dengan menginput transaksi pembelian Paracetamol sebanyak 15 buah oleh pasien ID 6. Setelah disimpan dan kita cek tabel obat, stok Paracetamol otomatis berkurang dari 100 menjadi 85."

Langkah 10 — Replikasi Tahap 2: Cek IP & Ping (Windows ↔ Ubuntu VirtualBox)
🖱 Aksi di VirtualBox, CMD Windows, dan Terminal Ubuntu:
  1. Di jendela VirtualBox: klik menu Machine → Settings → Network, tunjukkan bahwa Attached to menggunakan Host-Only Adapter (atau Bridged Adapter).
  2. Buka Command Prompt (CMD) di Windows, ketik ipconfig (lihat IPv4 VirtualBox Host-Only, biasanya 192.168.56.1).
  3. Buka Terminal di Ubuntu VirtualBox, ketik ip a (lihat IPv4 Ubuntu, misal 192.168.56.101).
  4. Tes ping dari CMD Windows: ping 192.168.56.101 dan dari Terminal Ubuntu: ping 192.168.56.1.
🎙 Kalimat yang Diucapkan:
"Sebelum menghubungkan replikasi ke Ubuntu di VirtualBox, kita pastikan pengaturan Network di VirtualBox menggunakan Host-Only Adapter. Kita cek IP di Windows menggunakan ipconfig dan di Terminal Ubuntu menggunakan ip a, lalu kita lakukan uji ping dua arah untuk memastikan kedua sistem operasi sudah saling terhubung."
Langkah 11 — Replikasi Tahap 3: Konfigurasi Slave Ubuntu & Pembuktian Real-Time
🖱 Aksi di Ubuntu VirtualBox:
  1. Nyalakan XAMPP di Terminal Ubuntu dan edit /opt/lampp/etc/my.cnf:
sudo /opt/lampp/lampp start
sudo /opt/lampp/bin/mysql_upgrade -u root --force
sudo chmod a+rwx /opt/lampp/etc/my.cnf
sudo nano /opt/lampp/etc/my.cnf
  1. Di dalam my.cnf di bawah [mysqld], beri tanda pagar pada #server-id = 1 dan tambahkan: 
    server-id=2
replicate-do-db=rumah_sakit
    Simpan (Ctrl + O, Enter, Ctrl + X), lalu jalankan: 
    sudo chmod 644 /opt/lampp/etc/my.cnf
sudo /opt/lampp/lampp restart
  2. Buka browser Firefox di Ubuntu (http://localhost/phpmyadmin) → buat database rumah_sakit → klik tab Import → impor file rumah_sakit.sql dari Windows tadi.
  3. Klik tab SQL di phpMyAdmin Ubuntu, lalu jalankan perintah ini (sesuaikan IP Windows, nama File, dan angka Position dari Langkah 9):
STOP SLAVE;
CHANGE MASTER TO
  MASTER_HOST='192.168.56.1',
  MASTER_USER='subhan',
  MASTER_PASSWORD='1234',
  MASTER_LOG_FILE='mysql-bin.000001',
  MASTER_LOG_POS=328;
START SLAVE;
  1. Klik tab Replication di phpMyAdmin Ubuntu → klik See slave status table (atau See replica status table) → tunjuk baris Slave_IO_Running: Yes dan Slave_SQL_Running: Yes!
  2. Uji Sinkronisasi Real-Time:
    • Di phpMyAdmin Windows (Master), buka tabel transaksi_obat → klik Insert → masukkan pembelian ke-2: id_pasien = 8 (Dudung), id_obat = 3 (Betadine), jumlah = 25, total_harga = 375000 → klik Go.
    • Tunjukkan di tabel obat Windows: stok Betadine berkurang dari 100 menjadi 75.
    • Pindah ke phpMyAdmin Ubuntu (Slave), klik Browse / Refresh pada tabel transaksi_obat dan tabel obat: tunjukkan transaksi ke-2 otomatis masuk dan stok Betadine di Ubuntu otomatis berkurang menjadi 75!
🎙 Kalimat yang Diucapkan (Sekaligus Penutup):
"Di sisi Slave Ubuntu, kita mengimpor database rumah_sakit.sql, mengatur file my.cnf dengan server-id=2 dan replicate-do-db=rumah_sakit, merestart XAMPP Ubuntu, lalu menjalankan perintah STOP SLAVE, CHANGE MASTER TO sesuai IP Master Windows serta posisi log-nya, dan START SLAVE. Pada tabel status replica terlihat Slave_IO_Running dan Slave_SQL_Running keduanya bernilai Yes. Terakhir kita uji dengan menambahkan transaksi pembelian 25 Betadine di Master Windows sehingga stoknya turun dari 100 menjadi 75. Ketika kita refresh phpMyAdmin di Ubuntu, data transaksi kedua otomatis muncul dan stok Betadine di Ubuntu juga otomatis berkurang menjadi 75.
